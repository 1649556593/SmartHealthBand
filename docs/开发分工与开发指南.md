## 0. 一分钟摘要

1. 工程已上 GitHub，**可以开工**。
2. 实物是**正点原子 ESP32-S3 开发板 + 4.3 寸 RGB 并口屏**，**不是**课程方案里写的 SPI 屏 + FT6236 触摸。
3. 现有代码只有**屏幕、触摸、LVGL 移植**，跑的是厂商音乐播放器 demo：**没有传感器驱动、没有算法、没有业务逻辑、没有手环页面**。
4. 第一阶段目标不变，仍是课程方案的必做闭环：**计步 → 久坐判定 → 震动 + 弹窗 → 用户反馈 → 复位**。
5. 但实现顺序必须务实：先补 **I2C 扫描 → MPU6050 → 按键 → 马达**，这四项是后面所有功能的地基。

## 2. 实物事实：必须放弃方案里的那套引脚

课程方案（以及《六人详细分工说明》）是按 **SPI 屏 + FT6236 + 直连 GPIO** 写的，我们手里的板子**不是这套**。开工前把下面这张表钉在心里：

| 项目 | 课程方案写的 | **我们实物实际是** |
|---|---|---|
| 显示屏 | 4.3" IPS 800×480，**SPI**（SCK12/MOSI11/CS10/DC14/RST15/BL16） | **RGB 并口 16 位**，DE=4、PCLK=5，R/G/B 数据线占 GPIO 3–48 一片 |
| 触摸 | **FT6236**，I2C `0x38`，INT17/RST18 | **GT9xxx 系列**，I2C `0x14`，INT=GPIO40，复位走 XL9555 |
| I2C 总线 | GPIO8=SDA / GPIO9=SCL | **GPIO41=SDA / GPIO42=SCL**，400 kHz |
| 按键 | 6×6 轻触接 **GPIO4** | 板上 KEY0–KEY3 挂在 **XL9555 扩展 IO** 上 |
| 背光 / 触摸复位 | 直连 GPIO16 / GPIO18 | 走 **XL9555**（`LCD_BL_IO` / `CT_RST_IO`） |
| 马达 | GPIO5，4 kHz PWM | **尚未确定**（见待确认清单第 4 项） |
| LVGL | 8.3 | **8.4.0** |
| ESP-IDF | 5.x | **5.3.5** |

### 铁律

> **代码一律以实物为准。课程方案只用来确定"做什么功能、达到什么指标"，不用来确定"接哪个引脚"。**

## 3. 环境搭建（每人必做，约 1 小时）

### 3.1 本机已有的东西

- ESP-IDF 框架：`D:\Espressif\frameworks\esp-idf-v5.3.5`
- 工具链根目录：`IDF_TOOLS_PATH = D:\Espressif`
- ⚠️ **`idf.py` 不在全局 PATH**，必须用 ESP-IDF 提供的命令行环境

### 3.2 打开 ESP-IDF 命令行

任选一种：

- 开始菜单搜索 **“ESP-IDF 5.3.5 PowerShell”**（推荐）
- 或手动执行：`D:\Espressif\frameworks\esp-idf-v5.3.5\export.ps1`

验证：

```powershell
idf.py --version        # 应输出 ESP-IDF v5.3.5
```

### 3.3 克隆工程并编译

```powershell
git clone https://github.com/1649556593/SmartHealthBand.git
cd SmartHealthBand
idf.py build
```

- 首次 `build` 会联网下载 `lvgl/lvgl 8.4.0` 到 `managed_components/`（该目录不入库）
- **不要**运行 `idf.py set-target esp32s3`：`sdkconfig` 已配置好目标和屏幕相关选项，重设目标可能把配置冲掉
- **不要**随手 `idf.py fullclean`：会重新拉依赖、重编全部组件，浪费时间

### 3.4 烧录与看日志

```powershell
idf.py -p COM3 flash monitor     # COM 口按设备管理器实际情况改（本机现有 COM3、COM4）
```

- 串口波特率 115200，控制台走 UART0，同时开启了 USB Serial/JTAG 备用
- 退出监视器：`Ctrl + ]`

### 3.5 环境自查（三条都过才算搭好）

- [ ] `idf.py --version` 输出 v5.3.5
- [ ] `idf.py build` 成功，生成 `build/smart_health_band.bin`
- [ ] `idf.py -p COMx flash monitor` 能看到启动日志、屏幕亮起并显示厂商音乐播放界面

## 4. Git 协作规范

### 4.1 分支约定

| 分支 | 规则 |
|---|---|
| `main` | **始终保持可编译、可运行**。任何人不得直接往 `main` 强推 |
| `feature/xxx` | 每个人的功能分支，如 `feature/mpu6050-driver`、`feature/step-counter` |
| 合并 | 功能分支完成后发 Pull Request，**至少 1 名组员 review + 能编译** 才可合并 |

### 4.2 日常流程

```powershell
# 1. 开工前先同步主干
git checkout main
git pull --rebase origin main

# 2. 建自己的功能分支
git checkout -b feature/mpu6050-driver

# 3. 改代码，本地编译通过后再提交
idf.py build
git add <你改的文件>
git commit -m "feat: 实现 MPU6050 初始化与 14 字节突发读"

# 4. 推送前再次同步主干，避免被拒
git pull --rebase origin main
git push -u origin feature/mpu6050-driver
```

然后在 GitHub 上发起 Pull Request，写清：**改了什么、硬件依赖、怎么验证、有什么已知问题**。

### 4.3 提交信息规范

格式：`类型: 动词 + 对象 + 原因`

| 类型 | 用途 |
|---|---|
| `feat` | 新功能 |
| `fix` | 修 bug |
| `docs` | 文档 |
| `refactor` | 重构，不改行为 |
| `test` | 测试 |

示例：

```
feat: 新增 I2C 设备扫描并打印地址
fix: 修正触摸坐标在 800×480 下的 Y 轴翻转
docs: 补充实物引脚表
```

### 4.4 禁止事项

- ❌ `git push -f` 到 `main`
- ❌ 提交 `build/`、`managed_components/`（`.gitignore` 已排除，别用 `-f` 强行加）
- ❌ 直接改别人的驱动文件而不打招呼
- ❌ 提交编译不过的代码到 `main`
- ❌ 一个人一次性提交几千行、没人看得懂的 PR

### 4.5 冲突高发区（提前打招呼）

| 文件 | 冲突原因 | 处理方式 |
|---|---|---|
| `sdkconfig` | 各自改了 menuconfig | **先找组长**，统一改并说明原因 |
| `main/APP/lvgl_demo.c` | 成员 3（显示/触摸）与成员 6（页面）都要动 | 约定：底层适配归成员 3，页面归成员 6，另开文件 |
| `main/CMakeLists.txt` | 各人加新目录 | 加之前先同步主干 |

## 5. 接口冻结（开工前 1 天完成，组长主持）

**目的**：避免六个人各写一套不兼容的结构体。字段名和单位一旦定下就不要再改。

### 5.1 建议的分层（渐进式，不要求一步到位）

```text
main/
├── main.c                  # 入口：只做初始化和创建任务
├── hal/                    # I2CBus / Gpio / Pwm / Nvs
├── driver/                 # mpu6050 / max30102 / tmp117 / gt9xxx / rgblcd
├── service/                # sensor_hub / step / sedentary / settings
└── app/                    # 页面、页面管理、提醒弹窗
```

**跨层调用禁令**（代码评审按这三条查）：

- `app/` 里不允许出现 `i2c_master_` 开头的 API
- `driver/` 里不允许出现 `lv_` 开头的 API
- `service/` 里不允许直接操作 GPIO

### 5.2 统一数据结构（待组长确认后冻结）

```c
/* 运动数据：成员 2 产生，成员 4 消费 */
typedef struct {
    float    ax, ay, az;      /* 加速度，单位 g */
    float    gx, gy, gz;      /* 角速度，单位 °/s */
    int64_t  timestamp_us;    /* 采样时刻，单调递增（esp_timer_get_time） */
} ImuData;

/* 运动结果：成员 4 产生，成员 5、6 消费 */
typedef struct {
    uint32_t total_steps;     /* 今日总步数 */
    float    cadence;         /* 步频，步/分 */
    float    activity_level;  /* 活动强度，无量纲 */
    bool     valid_activity;  /* 是否为"有效活动"（供久坐判定） */
} StepResult;

/* 久坐状态：成员 5 产生，成员 6 消费 */
typedef enum {
    SIT_WEAR_OFF = 0, SIT_ACTIVE, SIT_SITTING, SIT_ALERTING, SIT_SNOOZED, SIT_QUIET
} SitState;
```

| 接口 | 提供者 | 使用者 | 说明 |
|---|---|---|---|
| `i2c_scan_devices()` | 成员 2 | 全员 | 上电扫描并打印在线设备地址 |
| `mpu6050_init()` / `mpu6050_read(ImuData*)` | 成员 2 | 成员 4 | 50 Hz 采样，带时间戳 |
| `display_init()` / `touch_init()` | 成员 3 | 成员 6 | 已有厂商实现，做一层封装 |

| `step_counter_update(const ImuData*)` / `step_counter_get(StepResult*)` | 成员 4 | 成员 5、成员 6 | 输入 IMU，输出步数/步频/活动强度 |

### 成员 2 · 硬件与传感器驱动

**负责文件**：`main/hal/i2c_bus.*`、`main/driver/mpu6050.*`（后续 `max30102` / `tmp117`）、`docs/硬件接线.md`

**任务**

1. **接线表与实物照片**：核对开发板与模块引脚，确认 3.3 V / GND 共地（**不要照抄方案里的 GPIO8/9**）
2. **I2C 扫描程序**：在现有 `myiic_init()`（GPIO41/42）基础上，加设备探测与地址打印，目标看到 `0x20`(XL9555) 与三颗传感器
3. **MPU6050 驱动**：读 `WHO_AM_I`(0x75，应为 `0x68`) → 复位 → 时钟源 → 采样率分频(0x19=19 → 50 Hz) → DLPF 21 Hz(0x1A=0x04) → 陀螺 ±500 °/s(0x1B=0x08) → 加速度 ±4 g(0x1C=0x08) → **回读校验**
4. **14 字节突发读** 从 `0x3B` 起，原始值换算成 g 与 °/s，附加 `esp_timer_get_time()` 时间戳
5. **200 样本零偏校准**：静止时陀螺输出应 < 0.5 °/s
6. **CSV 数据导出**：静止 / 走路 / 跑步各一段，交给成员 4 调算法
7. 统计丢样率（连续采样 10 分钟应 < 0.1%）

**交付物**：I2C 扫描与自检程序、MPU6050 驱动、`ImuData` 输出接口、CSV 数据、接线表与照片

**验收**：I2C 能扫到目标设备；50 Hz 稳定采样；静止陀螺 < 0.5 °/s；丢样率 < 0.1%

**不要做**：不实现计步算法本身

### 成员 4 · 运动算法（计步）

**负责文件**：`main/service/step_service.*`、`docs/算法说明.md`、`tools/`（数据回放）

**任务**

1. 用成员 2 的 CSV 数据先在 PC 侧验证算法（**不必等硬件全通**）
2. 计算合加速度 `SVM = √(ax²+ay²+az²)`，先做一阶低通（`m_lp += 0.2f*(svm-m_lp)`）
3. 5 s 滑动窗口（50 Hz × 5 s = 250 点）算均值与标准差，动态阈值 `μ + 0.8σ`（**禁止写死固定阈值**）
4. 峰谷检测：上穿阈值记候选峰，峰谷差 ≥ 0.6 g 且峰间隔在 250–2000 ms 之间才计一步
5. 输出 `StepResult`：总步数、步频、活动强度、有效活动标志
6. 距离/热量估算（步长 0.65 m、0.04 kcal/步），界面必须标注"约"
7. **马达屏蔽**：震动期间及之后 300 ms 内暂停计步（依赖成员 3 的接口，先用标志位模拟）
8. 100 步基准测试：5 组，统计误计率与漏计率

**交付物**：计步与活动强度代码、CSV 测试数据、SVM 波形图、100 步基准记录、误计/漏计统计、算法说明文档

**验收**：走路时步数正确增加；误计率 < 3%、漏计率 < 5%；支持清零与每日复位

**不要做**：不直接控制屏幕和马达

### 成员 5 · 久坐业务逻辑

**负责文件**：`main/service/sedentary_service.*`、`docs/久坐状态机.md`

**任务**

1. 先画状态机图：`WearOff / Active / Sitting / Alerting / Snoozed / Quiet` 六态，写清每个迁移的**条件、事件、动作**
2. **计时用单调时钟做差**（`esp_timer_get_time()`），不用 `delay`、不依赖系统时间（防止改时间绕过提醒）
3. 阈值从设置服务读取，默认 45 min，支持 30/45/60
4. 有效活动判定：与成员 4 统一为"**5 分钟内 ≥ 30 步**或活动强度达中等以上"，阈值满足后清零并回 `Active`
5. 提醒执行：调 `motor_vibrate()` 播"震 2 s、停 1 s，共 3 次"（非阻塞），并向 UI 发提醒事件
6. 稍后逻辑：`稍后 10 分钟`、最多连续 3 次、弹窗 60 s 无操作自动稍后
7. 免打扰时段（默认 22:00–07:00）只暂停提醒、保留计时
8. 页面切换、熄屏**都不能**影响计时

**交付物**：状态机图、久坐业务代码、提醒事件定义、免打扰逻辑、久坐测试用例、45 min 计时测试记录

**验收**：连续 45 min 无有效活动触发提醒，计时误差 ≤ 10 s；稍后 3 次仍能再次提醒；有效活动后正确复位；熄屏/切页不影响计时

**不要做**：不重写传感器驱动和 UI

### 成员 6 · LVGL 图形界面

**负责文件**：`main/app/`（页面、页面管理、弹窗）、`main/app/theme.h`

**任务**

1. LVGL 页面管理框架：六页面环形切换（表盘 → 运动 → 心率血氧 → 体温 → 久坐 → 设置），左右滑动 + 底部页点
2. 六个页面：表盘（时间/日期/固定 100% 电量/步数）、运动（步数进度/距离/热量/活跃时长/近 7 天柱状图）、心率血氧（显示"未启用"，**禁止假数据**）、体温（"未启用"）、久坐（已坐时长/倒计时/免打扰状态）、设置（阈值/震动强度/亮度，改完调设置服务保存）
3. 久坐提醒弹窗：全屏遮罩 + "已起身" / "稍后 10 分钟"，点击后把事件交给成员 5
4. 统一主题：深色底 `#0B1220`、卡片 `#152238`、主文字 `#F8FAFC`、强调色青绿 `#2DD4BF` / 红 `#FF5A6E` / 琥珀 `#FBBF24`
5. 规范落地：触摸目标 ≥ 48×48 px、主要按钮高 ≥ 52 px、正文 ≥ 18 px、关键数值 40–112 px
6. **禁止在 UI 里重复实现计步和久坐算法**，只消费成员 4/5 的数据
7. 中文用 `lv_font_conv` 生成子集字体（只取界面用到的 300–500 字），避免整字体塞 Flash

**交付物**：LVGL 初始化与页面管理、六个页面、提醒弹窗、设置页、UI 截图、页面操作测试记录

**验收**：六页均可进入与操作；未启用页面明确标注；表盘/运动页显示真实步数；久坐页显示成员 5 的真实状态；设置能保存

## 9. 排障速查

| 现象 | 可能原因 | 排查 | 解决 |
|---|---|---|---|
| 屏幕白屏/花屏 | 屏 ID 判断错、排线接触、复位时序 | 串口打印 `lcddev.id`；重插 FPC 排线 | 确认 `0x4342` 还是 `0x4384`；加复位延时 |
| 触摸坐标偏移 | 分辨率映射错、横竖屏未交换 XY | 打印原始坐标，与屏幕四角对比 | 按实际分辨率修正映射 |
| I2C 扫不到设备 | 供电、上拉、地址（AD0/ADD0）、线序 | 万用表测 3.3 V；确认 GPIO41/42 | AD0/ADD0 接地；补 4.7 kΩ 上拉；换杜邦线 |
| `idf.py` 找不到 | 未进入 ESP-IDF 命令行 | `Get-Command idf.py` | 用 "ESP-IDF 5.3.5 PowerShell" 或跑 `export.ps1` |
| 烧录失败 / 串口被占用 | COM 口选错、别的软件（串口助手）占着 | 设备管理器看端口 | 关闭占用程序；换 COM4 |
| 编译报 PSRAM / Flash 相关错 | `sdkconfig` 被改 | `git diff sdkconfig` | `git checkout sdkconfig` 后重编；要改先找组长 |
| 首次 build 卡住 | 联网下载 LVGL 组件 | 看日志是否在下载 | 确保网络可用，或从别人机器拷 `managed_components/` |
| 步数乱跳 | 阈值太低、马达震动耦合、佩戴松 | 静止与走动各记录 1 min 数据 | 提高阈值系数；震动期间屏蔽；贴紧表带 |
| 随机死机 | 栈溢出、I2C 死锁、未喂狗 | 看 panic 回溯 | 增大栈；缩小锁粒度；加看门狗 |
